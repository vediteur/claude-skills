# codex-image

Claude Code 는 묘사·요청·검수만 하고, 이미지는 Codex 가 만든다. Higgsfield 에는 올리지 않는다(등록은 사람이 한다).

`unse-shorts` 저장소 전용이다. 아래 경로는 모두 그 저장소 루트 기준이다. Codex CLI(`codex exec`)가 설치·로그인돼 있고 내장 image_gen 을 쓸 수 있어야 한다.

## 1. 무엇을 만들지 정하기

1. `PROJECT_STATUS.md` 와 바이블 `story/series_bible.md` "등록 에셋" 표를 읽는다.
2. 사용자가 이름을 댔으면 그것을, "대본에 필요한 에셋"처럼 말했으면 해당 대본(`story/season1/*.md`)과 파트 분할표를 읽어 등록 에셋 표에 없는 인물·장소·소품을 골라 목록으로 보여 준다. 여러 개면 한 번에 하나씩 요청하지 말고 한 Codex 요청에 묶는다.
3. 종류별 태그 이름·저장 경로를 정한다. 파일 이름은 `@태그.png`, 프롬프트 기록은 `@태그-prompt.txt` 로 같은 폴더에 둔다.

| 종류 | 태그 규칙 | 저장 폴더 | 예 |
| --- | --- | --- | --- |
| 인물 | `{영문이름}_v{n}` | `master/characters/{영문이름}/master/` | `master/characters/yeoni/master/@yeoni_v1.png` |
| 장소 | `loc_{장소}_{낮/밤}_{앵글·구역}_v{n}` (책방은 `loc_bookshop_…`) | 책방 `assets/bookshop/…`, 그 밖 `assets/backgrounds/{장소}/` | `assets/backgrounds/gwana/@loc_gwana_gate_day_v1.png` |
| 소품 | `prop_{물건}_v{n}` | `assets/props/` | `assets/props/@prop_ledger_v1.png` |

- 영문은 소문자·밑줄만. 로마자는 정묘=jeongmyo, 연이=yeoni 처럼 붙여 쓴다.
- 같은 태그가 표나 폴더에 이미 있으면 버전을 올린다(`_v2`). 기존 파일은 덮어쓰지 않는다.
- `master/` 는 AGENTS.md 상 읽기 전용이지만, 사용자가 이 스킬로 인물 생성을 요청한 것이 그 폴더·파일 쓰기에 대한 지시다. 요청문에 그렇게 밝힌다.

## 2. 외형 묘사 쓰기 (Claude)

출처를 이 순서로 모아 구체적으로 쓴다. 대본에 없는 것은 시리즈 톤(판타지 조선, 실사 시네마틱)에 맞게 정하고, 정한 것은 보고할 때 "제가 정한 것"으로 따로 알린다.

1. 대본 지문·등장인물 줄(나이·신분), 일주 캐릭터 카드(비유·오행·인물 칸)
2. 파트 분할표·프롬프트 파일에 이미 쓴 묘사 — 영상 프롬프트와 어긋나지 않게 같은 색·소재·머리 모양을 쓴다
3. 바이블(세계관, 오행 이펙트 색, 폭력 수위)과 기존 시트 이미지 — 정묘·다미 시트를 열어 형식과 질감을 맞춘다

인물은 나이·체구·얼굴 인상·머리·옷(색+소재+상태)·손 같은 고유 표식을 쓴다. 기존 인물과 얼굴이 겹치지 않게 "○○와 다른 얼굴"을 명시한다. 미성년 인물은 단정하고 노출 없는 차림을 검수 기준에 넣는다.

## 3. 종류별 형식

- **인물 시트**: 가로 16:9 한 장, 세로 경계선 3분할, 균일한 중간 회색 무지 배경, 고른 스튜디오 조명, 실사 사진 질감. ① 정면 전신(목 아래부터 발끝, 머리는 화면 밖) ② 정후면 전신(머리 포함) ③ 정면 얼굴 클로즈업(어깨 위, 입 다묾). 형식 참조 `master/characters/jeongmyo/master/jeongmyo-sheet.png` — 판 구성·배경·질감만 따르고 얼굴·옷은 따르지 않는다.
- **소품 시트**: 가로 16:9, 3분할, 회색 무지 배경. ① 정면 전체 ② 열리거나 펼친 상태 등 쓰임새 ③ 디테일 확대. 형식 참조 `assets/props/02-fortune-book-sheet-v2.png`.
- **장소**: 세로 9:16 한 장, 화면을 꽉 채운 실사 시네마틱 장소 사진, 사람·실루엣 없음. 같은 장소의 다른 앵글이면 기존 장소 이미지를 참조로 지정해 건물·재질·색을 잇는다. 형식 참조 `assets/bookshop/exteriors/bookshop-location-assets-v2/bookshop-location-assets-v2-images/`.
- 모든 이미지: 읽히는 글자·숫자·로고·워터마크·패널 번호 없음.

## 4. Codex 요청 (백그라운드)

요청문을 스크래치패드에 `{태그}-request.md` 로 쓴다. 들어갈 것:

- 생성은 Codex 내장 image_gen 만. Higgsfield 호출·업로드 금지.
- 결과 파일 경로(정확히)와 `@태그-prompt.txt` 에 실제 쓴 전체 프롬프트 저장. 폴더가 없으면 만든다.
- 그 밖의 파일은 만들거나 고치지 않는다(`PROJECT_STATUS.md`, `story/`, 다른 캐릭터·에셋 폴더 포함). 커밋·푸시 금지.
- 형식(3절)과 외형 묘사(2절), 형식 참조 파일.
- 검수 기준과 재생성 최대 2회.
- 끝나면 경로·크기(px)·재생성 횟수·검수 결과를 짧게 보고.

실행:

```bash
cd <저장소 루트> && codex exec -s workspace-write "$(cat <요청문 경로>)" 2>&1 | tail -40
```

Bash `run_in_background: true` 로 돌린다. 시작하면 `PROJECT_STATUS.md` §2 진행 중에 "Codex (Claude Code 가 사용자 지시로 `codex exec` 백그라운드 요청, HH:MM 시작): …, 결과 확인 전"을 적는다. 기다리는 동안 결과를 지어내지 않는다.

## 5. 결과 확인

1. 출력의 마지막 보고를 읽고, 이미지를 직접 연다(Read). 검수 기준·외형 묘사와 대조한다. 어긋난 점(Codex 가 놓친 것 포함)을 그대로 보고한다.
2. 바이블 "등록 에셋" 표의 알맞은 절(인물·장소·소품)에 한 줄 추가: 태그 · 이름 · 기준 파일 · `미등록 (시트 완성 YYYY-MM-DD)`.
3. 그 에셋을 쓰는 파트 프롬프트(`story/season1/*-prompts.md`)에 글 묘사만 있던 줄이 있으면 태그 줄로 바꾼다.
4. `PROJECT_STATUS.md` 진행 중 항목을 결과로 바꾼다: 경로·크기·sha256 앞 12자·재생성 횟수·Claude Code 검수 결과·사용자 채택 전.
5. 사용자에게 채택 여부를 묻고, 등록 이름(앞의 `@` 를 뺀 태그)을 알려 준다. 사용자가 등록했다고 하면 `codex exec -s read-only` 로 이름·상태·이미지 수를 조회해 표를 "확인"으로 바꾼다.
