# UX 라이팅 4대 가이드라인 — 상세

각 원칙마다 "무엇을 / 왜 / 어떻게 고치는지"와 적용 예시를 둔다. 예시는 원리를 보여주기 위한 것이며, 실제 프로젝트에서는 브랜드 톤에 맞게 다시 쓴다.

---

## 1. 간결하게 쓰기

### 1-1. 극존칭 지우기
- "~하시겠습니까?", "~해주시기 바랍니다" 같은 과잉 경어는 문장을 길게 만들고 딱딱하게 들린다.
- "~할까요?", "~해주세요"로 바꾼다.
- 예: "서비스를 종료하시겠습니까?" → "서비스를 종료할까요?" / "메시지를 보내시겠습니까?" → "메시지를 보낼까요?"

### 1-2. 반복되는 말 지우기
- 두 문장이 같은 사실을 말하면 하나로 합친다.
- 예: "아쉽지만 이번 주는 당첨되지 않았어요 / 다음 주에 다시 응모할 수 있어요" → "당첨되지 않았어도 다음 주 기회가 있어요"

### 1-3. 의미 없는 정보 지우기 (당연한 건 말하지 않는다)
- 화면에 이미 보이는 것을 문장으로 다시 설명하지 않는다("아래 그림처럼").
- 사용자가 하지 않을 행동을 굳이 안내하지 않는다.
- 예: 다른 기기 로그인 알림에서 "혹시 본인이 아니라면 알려주세요"는 알림의 핵심("다른 브라우저에서 로그인됐어요")만 남기고 뺄 수 있는지 검토한다.

### 1-4. 채널 규칙 안에서 핵심을 앞에
- 문자·푸시는 앞 20자 안에 핵심이 보여야 한다. 법적 표기("(광고)")는 제목이 아닌 본문에 두는 등 채널 규칙을 확인한다.

### 1-5. 짧다고 정답이 아니다
- 줄였는데 "무엇이 얼마나"가 빠지면 실패. 2번(명확하게)과 항상 같이 본다.
- 미니 실습: "쇼핑 10% 할인 쿠폰을 받으시겠습니까?" → "10% 할인 쿠폰을 받을까요?" (경어 정리, 맥락상 뻔한 "쇼핑" 제거, 핵심 숫자는 유지)

## 2. 명확하게 쓰기

### 2-1. 쉽게 — 소리 내서 말하듯
- 입으로 말했을 때 어색하면 고친다.
- 예: "탈퇴를 선택하셨습니다. 탈퇴 후 재가입 의향이 있으신가요?" → "탈퇴하지만, 다시 만날 수 있을까요?"

### 2-2. 쉽게 — 한자어·영어·내부 용어 바꾸기
- 내부에서 익숙한 용어도 고객에게는 처음 듣는 말이다.
- 예: "은행명이 올바르지 않습니다" → "은행 이름을 다시 확인해주세요"
- 예: "인증번호 유효시간이 만료됐어요" → "인증번호 입력 시간이 지났어요"
- 예(자동차): "스위블 시트" → "시트 회전 기능", "워크인 모드" → "3열 승객 승하차 모드"

### 2-3. 쉽게 — 바로 이해되게 / 단어 하나로 오해가 생기지 않게
- 다의어("디자인 진행" — 내가 하는 건지 맡기는 건지)를 피하고, 사용자가 하는 행동을 그대로 쓴다.
- 예: "간판 디자인 외주 디자인 진행" → "간판 디자인 맡기고, 페이백까지 받아가세요"
- 두 개 이상의 메시지를 한 문장에 넣지 않는다. 필요하면 화면을 나눈다.

### 2-4. 정확하게 — 두괄식
- 가장 중요한 결론·혜택·요청을 첫 문장에. 배경 설명은 뒤로.
- 사과문, 공지, 장문 알림에서 특히 중요하다. 인사·회사 소개·경위 설명이 앞을 차지하면 사용자는 끝까지 읽지 않는다.

### 2-5. 정확하게 — 질문에는 답이 바로
- 제목이 질문형이면 첫 문장이 답이어야 한다. 답을 미루고 배경을 먼저 설명하지 않는다.

### 2-6. 정확하게 — 진짜 "취소"가 아니면 취소 워딩 금지
- "취소"는 예약·송금처럼 되돌리는 행위에만 쓴다. 대화 종료, 화면 나가기에 "취소"를 쓰면 무엇이 취소되는지 헷갈린다.
- 예: "상담톡을 종료하시겠습니까? [취소] [확인]" → "상담톡을 끝낼까요? [계속하기] [끝내기]"

### 2-7. 정확하게 — 타이틀과 버튼이 호응
- 타이틀이 "끝낼까요?"면 버튼은 "끝내기/계속하기". 타이틀은 "종료"인데 버튼은 "확인/취소"면 어긋난다.

### 2-8. 정확하게 — 타이틀부터 제대로
- "안내", "알림" 같은 무의미한 타이틀 대신 사건 자체를 타이틀로.
- 예: 타이틀 "안내" + 본문 "고객님의 안전한 정보 보호를 위해 일정 시간 사용하지 않은 경우 서비스를 강제 종료합니다" → 타이틀 "자동으로 로그아웃됐어요" + 본문 "개인정보를 보호하기 위해서예요. 다시 로그인해주세요"

### 2-9. 정확하게 — 질문은 한 번만
- 타이틀에서 "끝낼까요?" 하고 본문에서 또 "계속할까요?" 묻지 않는다.
- 예: "상품 가입을 끝낼까요? / 끝내면 입력한 내용은 저장되지 않습니다. 계속할까요?" → "대화를 끝낼까요? / 여기서 그만두면 처음부터 다시 해야 해요"

### 2-10. 결과를 예상할 수 있게 — 구체적으로
- 구체적일수록 좋다. "얼마나 해야 하지?" 하고 멈칫하는 순간을 없앤다.
- 예: "10월 금융 미션이 나왔어요" → "금융 미션 4개가 나왔어요"
- 예: "빈칸 채우고 받기" → "8칸 채우고 포인트 받기"

### 2-11. 결과를 예상할 수 있게 — 다음 화면 힌트
- 버튼 문구를 보고 누른 뒤 나오는 화면이 예상과 다르면 신뢰가 깨진다. 궁극적 혜택("~하면 제휴 브랜드가 늘어요")을 설명하느라 바로 다음에 일어나는 일("설문이 나옵니다")을 빠뜨리지 않는다.

## 3. 모두를 위해 쓰기

### 3-1. 유저 입장에서 생각하기
- 공급자는 사전 지식 때문에 무의식적으로 어렵게 쓴다. "친구에게 이 소식을 전한다면?"으로 다시 쓴다.
- 모든 맥락을 설명하는 것이 친절이 아니다. 두 선택지의 차이만 딱 보이게 정보를 생략하는 편이 더 친절할 때가 많다(예: 추가 상환 화면에서 "금액 직접 입력" vs "다음 달 낼 금액 자동 납부").
- 정보 전달을 넘어, 그 정보를 받는 순간의 감정을 생각한다(에러·거절·실패 메시지에서 특히).
- 안 되는 이유를 나열하는 대신 "그래서 무엇을 하면 되는지"를 준다. 예: "해당 계좌는 비밀번호 사후등록 계좌입니다" → "비밀번호가 등록되지 않은 계좌예요. 다른 계좌로 바꾸기를 추천해요"

### 3-2. 제목부터 재미있게 (콘텐츠·기사형)
- 같은 내용도 제목에 따라 클릭이 갈린다. 한자어 나열형 제목은 기사처럼 읽혀 넘어간다.
- 예: "대형마트 영업 규제 민·관 심사 시작" → "대형마트 쉬는 날이 없어질 수 있다고?"

### 3-3. 유저가 모르는 말 지양
- 첫 진입 화면에서는 브랜드명, 이벤트명, 자사 서비스 명칭, 어려운 용어를 쓰지 않는다. 사용자는 그것이 무엇인지 아직 모른다.

### 3-4. 모두가 이해할 수 있고 상처받지 않게
- 업계에 따라 이해도가 갈리는 용어는 쉽게 바꾼다.
- 유행어·밈은 올드하지 않게 시의성 있게 쓰되, 특정 집단만 아는 말보다 사실 전달에 초점을 맞추면 모두가 이해하는 문장이 나온다.
- 특정 집단, 특히 소수자가 상처받을 표현을 피한다.

### 3-5. 선택권 존중 — 담백하고 중립적으로
- 의견을 단언하지 않는다. 이해관계가 얽힌 사안은 양쪽 입장 분량을 고르게.
- 혜택을 알려주는 것은 좋지만 강요·공포로 느껴지면 안 된다. 뉴트럴한 톤으로 혜택만 전달하고 선택은 사용자가.

### 3-6. 선택권 존중 — 메인 버튼을 유저 기대에 맞추기
- 메인(강조) 버튼이 무엇이냐에 따라 사용자가 받아들이는 의도가 달라진다. 이탈 방지 팝업에서 "계속하기"를 메인으로 두면 붙잡는 의도, "나가기"를 메인으로 두면 존중하는 의도가 된다. 화면 목표에 맞게 의식적으로 정한다.

### 3-7. 선택권 존중 — 겁 주는 부정적 어감 피하기
- "지금 안 하면 손해", "놓치면 끝" 같은 표현 대신 사실("오늘까지 신청할 수 있어요")만 담백하게.

## 4. 전환율 올리기

### 4-1. 베네핏 설명 / 즉각적 밸류
- 크고 불확실한 것보다 작고 확실한 것이 매력적이다.
- 예: "최대 100만 원 받기" vs "최소 100원 뽑기" → 후자가 노출·반응이 크게 높았다.
- 예: "원하는 만큼 마음껏 받아요" vs "1장은 무조건 받아요" → 후자.

### 4-2. 담백하게 — 광고가 아닌 기능·정보·뉴스처럼
- 예: "김토스님이 10월에 받을 수 있는 대출 확인하기" → "이달의 대출 목록 도착 · 모아보기"
- 예: "최대 10% 이득인 편의점 멤버십" → "새로 나온 편의점 혜택이 있어요 · 10원 받고 시작하기"

### 4-3. 얼마 안 남았다고 알려주기
- 남은 시간·수량을 사실대로. 3-7과 충돌하지 않게 공포 조성은 금지.

### 4-4. 왜 해야 하는지 설명해 고민 시간 없애기
- 행동의 이유(왜 지금, 왜 이걸)를 한 줄로 붙이면 망설임이 줄어든다.

### 4-5. 걱정·부담 덜어주기
- 소요 시간·필요 서류·비용을 먼저 명시: "여행자 보험 준비 아직이라면 / 3분 만에 가입하기"
- 오해가 생길 지점을 선제적으로 설명: 계좌 연결 시 은행에서 오는 안내 문자를 보고 "정기적으로 돈이 빠져나가나?" 하는 불안이 CS 문의 상위권이 됐던 사례 — 문구로 "출금이 아니라 확인용"임을 먼저 알리고, 인증 문자가 도착해도 안내 내용이 가려지지 않게 화면 배치까지 함께 바꿔 월 문의를 약 86% 줄였다. 문구와 레이아웃을 같이 본다.

## 좋은 문구인지 판단하고 설득하는 법

1. 변수를 하나로 제한한 A/B 테스트
2. 가이드라인 · 관련 아티클 · 타사 레퍼런스 찾기 (`brand-guides.md`)
3. 개선안만 내지 말고 문제 정의 → 가설 → 개선안 순으로 제시
4. 팀원 투표
