# UX 라이팅 스킬

UI 문구를 쓰거나 고칠 때 따르는 원칙과 절차. 한국어 B2C 서비스(핀테크·커머스·미디어·커뮤니티) 기준으로 작성됐다.

## 대전제

- **정답은 없다.** 좋은 문장은 목표(클릭·전환·CS 감소·신뢰)와 맥락(대상·시점·앞뒤 화면)에 따라 달라진다. 이전에 잘 됐던 문구도 반복 노출되면 반응이 약해진다. 항상 "이 화면의 목표가 무엇인가"부터 확인한다.
- **가이드라인보다 브랜드 내 통일성이 우선이다.** 프로젝트에 기존 라이팅 규칙(어미, 용어집, 톤)이 있으면 그것을 먼저 따르고, 이 스킬은 빈 곳을 채우는 용도로 쓴다.
- 문구만으로 해결되지 않는 문제(정보 위계, 버튼 배치, 인증 문자 팝업이 내용을 가리는 등)는 화면 배치 개선도 함께 제안한다.

## 작업 절차

문구를 새로 쓰든 고치든 아래 순서로 진행하고, 결과물에도 이 구조를 드러낸다.

1. **맥락 파악** — 어떤 화면/채널인가(다이얼로그·푸시·문자·버튼·상세페이지), 직전 화면과 다음 화면은 무엇인가, 목표 지표는 무엇인가, 브랜드 톤은 무엇인가. 모르면 짧게 질문하되, 합리적 가정을 명시하고 진행해도 된다.
2. **문제 정의** — 기존 문구가 있다면 사용자 입장에서 읽었을 때 어디서 멈칫하는지 구체적으로 적는다. ("이름이 빠져 있어 나에게 온 알림인지 확신이 안 든다", "'취소'가 무엇을 취소하는지 모호하다")
   - **기존 문구가 없는 신규 작성이면**, 그 컴포넌트에서 흔히 나오는 안티패턴(`references/components.md`의 각 섹션 "흔한 실수")을 Before로 세워 놓고 무엇을 피하는지 먼저 밝힌다. 비교 대상이 있어야 개선안의 근거가 보인다.
   - 개인화 변수(이름, 포인트, 날짜 등)를 쓰는 안은 값이 비었을 때의 **폴백 문구**를 반드시 함께 낸다.
3. **가설 설정** — "X를 Y로 바꾸면 Z가 개선될 것이다" 형태로 쓴다.
4. **개선안 작성** — 2~3안을 제시한다. 톤만 다른 안이 아니라, 강조점(혜택 강조 vs 담백한 정보형 vs 부담 해소)이 다른 안으로 구성한다.
5. **컴포넌트 규칙 적용** — `references/components.md`에서 해당 컴포넌트(다이얼로그·토스트·에러·푸시·빈 화면·버튼·폼 라벨)의 글자 수 제한, 구조, 버튼 규칙을 확인해 맞춘다.
6. **체크리스트 검증** — `references/checklist.md`를 훑고, 어긴 항목이 있으면 수정한다.
7. **설득 자료** — 상대를 설득해야 하는 상황이면 A/B 테스트 설계(변수 하나만 바꾸기), 참고 가이드라인 근거, 팀 투표 방법을 덧붙인다.

## 4대 가이드라인 요약

자세한 설명과 적용 예시는 `references/guidelines.md`를 읽는다.

### 1. 간결하게
- 극존칭·과잉 경어 제거: "~하시겠습니까?" → "~할까요?"
- 같은 뜻의 반복 제거, 당연한 정보 제거("아래 그림처럼", "본인이 아니라면 알려주세요" 같은 군말)
- 문자·푸시에서 "(광고)" 표기는 제목이 아닌 본문에 두는 등 채널 규칙을 지키되 핵심을 앞에 둔다.
- 단, 무조건 짧은 게 정답은 아니다. 짧아져서 정보가 빠지면 실패다.

### 2. 명확하게
- **쉽게**: 소리 내어 말하듯 쓴다. 한자어·영어·내부 용어를 일상어로 바꾼다("유효시간이 만료됐어요" → "입력 시간이 지났어요", "스위블 시트" → "시트 회전 기능").
- **정확하게**: 두괄식으로 가장 중요한 정보를 먼저. 질문했으면 답이 바로 나오게. 진짜 취소가 아니면 "취소" 안 쓰기("상담을 종료하시겠습니까?" → "상담을 끝낼까요?"). 타이틀과 버튼이 서로 호응하게. 타이틀·본문 전체에서 질문은 한 번만.
- **결과를 예상할 수 있게**: 숫자로 구체화("미션이 나왔어요" → "미션 4개가 나왔어요", "빈칸 채우고 받기" → "8칸 채우고 포인트 받기"). 버튼을 누르면 다음 화면에 무엇이 나올지 힌트를 준다.

### 3. 모두를 위해
- **유저 입장**: 공급자가 아는 맥락을 전제하지 않는다. 모든 맥락을 설명하는 것이 친절이 아니라, 필요한 것만 남기는 것이 친절일 때가 많다. 친구에게 말하듯 입말로.
- **모두가 이해할 표현**: 첫 진입 화면에서 브랜드명·이벤트명·업계 용어를 쓰지 않는다. 유행어·밈은 시의성 있게 쓰되 특정 집단만 아는 말은 피한다.
- **선택권 존중**: 담백하고 중립적으로. 공포·강요·조급함을 주는 어감("지금 안 하면 놓칩니다") 대신 혜택만 그대로 전달하고 선택은 사용자에게. 메인 버튼(강조 버튼)이 사용자의 기대와 맞아야 한다 — 이탈 방지 팝업에서 "계속하기"를 메인으로 둘지 "나가기"를 메인으로 둘지에 따라 의도가 달라진다.

### 4. 전환율 올리기
- **혜택·즉각적 가치**: "크지만 불확실한 것"보다 "작지만 확실한 것"이 더 반응이 좋다("최대 100만 원 받기" < "최소 100원 뽑기", "원하는 만큼 받아요" < "1장은 무조건 받아요").
- **담백하게**: 광고가 아니라 기능·정보·뉴스처럼 보이게("~님이 받을 수 있는 대출 확인하기" → "이달의 대출 목록 도착").
- **남은 시간·수량 알리기**, **왜 해야 하는지 이유를 붙여 고민 시간 없애기**.
- **걱정·부담 덜어주기**: 소요 시간 명시("3분 만에 가입하기"), 자동 출금 같은 오해가 생길 지점을 선제 설명.

## 콘텐츠·광고 카피(SNS, 상세페이지)

사용자는 0.1초 안에 볼지 말지 결정한다. 후킹 카피는 아래 5가지 중 최소 2개를 충족해야 한다. 자세한 것은 `references/content-hooks.md`.

1. 나와 관련이 있다  2. 공감이 된다  3. 재미있다  4. 나에게 도움이 된다  5. 새롭다

광고 콘텐츠도 같은 조건을 따르면 성과가 난다. 첫 문장(제목)이 클릭을 결정한다 — 한자어 나열식 제목은 기사처럼 읽히고 넘어간다.

## 참고 가이드라인

토스·뉴닉·숨고·구글 Material·애플 HIG의 라이팅 원칙과 공통점은 `references/brand-guides.md`에 정리돼 있다. "왜 이렇게 고쳤는지" 근거를 댈 때 인용한다.

## 출력 형식

- Before/After 표 또는 나열. After는 안별로 라벨(예: "혜택 강조안", "담백한 정보형", "부담 해소안")을 붙인다.
- 각 안 아래에 한 줄로 "어떤 원칙을 어떻게 적용했는지" 적는다.
- 타이틀/본문/메인 버튼/보조 버튼처럼 컴포넌트 단위로 표로 나눠 쓴다. 각 안 옆에 글자 수(공백 포함)를 적어 제한 초과 여부를 바로 볼 수 있게 한다.
- 마지막에 "체크리스트에서 걸린 것"과 트레이드오프(예: 두 줄 넘침, 개인화 변수 의존)를 한두 줄로 남긴다.
- 어미는 프로젝트 톤이 없으면 "~해요"체 기본, 어색한 문장만 "~합니다"체.
